# DB 마이그레이션

비즈니스 테이블 구조를 팀에서 확정한 뒤 `V1__create_initial_schema.sql`부터 추가합니다. 현재 `docs/ERD.drawio`는 개념적 ERD이며, 다음 항목을 확정해야 초기 DDL을 작성할 수 있습니다.

- 실제 테이블·컬럼의 영문 이름과 자료형·길이입니다.
- NULL 허용, 기본값, UNIQUE 제약과 인덱스입니다.
- FK의 삭제·수정 정책과 상태값 목록입니다.
- 계산 속성·평균 평점 캐시의 저장 여부입니다.

공통 기준은 `snake_case`, `utf8mb4`, `BIGINT AUTO_INCREMENT` PK, `{참조테이블}_id` FK, UTC `TIMESTAMP`입니다. 연결 테이블은 ERD의 복합 PK 표현과 공통 PK 기준을 함께 검토해 확정합니다.

SQL 파일 이름은 `V<순번>__<설명>.sql` 형식을 사용합니다. 이미 적용한 파일은 수정하지 않고 다음 버전 파일로 변경합니다. Flyway가 스키마 변경을 담당하며, Hibernate 자동 DDL이나 Python의 `create_all()`로 별도 구조를 생성하지 않습니다.

환경 확인을 위한 가짜 테이블이나 빈 초기 마이그레이션은 만들지 않았습니다. SQL 파일을 추가하기 전에는 애플리케이션 테이블이 없는 상태가 정상입니다.
