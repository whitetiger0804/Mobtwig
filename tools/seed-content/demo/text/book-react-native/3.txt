3장 · 입력과 상태를 다룹니다

독자가 검색창에 글자를 입력하면 화면은 처음 실행했을 때와 다른 값을 기억해야 합니다. 컴포넌트가 화면을 그리는 데 사용하는 이러한 변화 가능한 값을 상태라고 부릅니다. 우리는 검색어를 query라는 상태로 두고 입력 칸에 그 값을 표시합니다. 입력이 바뀌었다는 이벤트를 받으면 상태를 갱신하며, React는 새 상태를 바탕으로 화면을 다시 계산합니다.

단순한 지역 변수에 글자를 대입하는 것만으로는 화면 갱신을 요청한 것이 되지 않습니다. 함수 컴포넌트에서는 useState와 같이 상태를 다루는 방법을 사용합니다. 현재 값과 그 값을 바꾸는 함수를 함께 생각하면 이해하기 쉽습니다. 입력 칸이 보여 주는 값과 검색에 사용하는 값을 별도로 복사해 두지 않고 하나의 상태를 사용하면, 두 값이 서로 어긋날 가능성을 줄일 수 있습니다.

책 목록에서 검색 결과는 목록과 검색어로부터 계산할 수 있습니다. 이 결과를 다시 별도 상태로 저장하기 전에 정말 독립적으로 바뀌는 값인지 묻습니다. 검색어만 바뀌면 결과도 다시 계산하면 되는 간단한 경우에는 중복 저장이 필요하지 않습니다. 즐겨찾기처럼 이전 값에 따라 바뀌는 배열은 기존 배열을 직접 수정하기보다 바뀐 내용을 담은 새 배열로 갱신하는 흐름을 연습합니다.

확인은 작은 행동 순서로 합니다. 글자를 입력하고 한 글자를 지운 뒤 입력을 모두 비웠을 때 각각 어떤 목록이 나와야 하는지 적습니다. 검색어가 없어졌는데 이전 결과가 남는다면 상태를 여러 곳에 중복해 둔 것은 아닌지 살핍니다. 상태는 모든 값을 모아 두는 창고라기보다 화면이 기억해야 할 최소한의 사실입니다. 다음 장에서는 선택한 책을 다른 화면에서도 알아볼 방법을 정합니다.
