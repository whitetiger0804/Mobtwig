# 본문 데이터와 독서 위치 규약

규약 v1 · 2026-11-06 · 관련 이슈: [#18](https://github.com/whitetiger0804/Mobtwig/issues/18)

## 적용 범위와 결정 근거

본문 열람(#35), 이어보기(#38), 북마크(#39), 하이라이트(#40), 설정집(#49~52)이 공유하는 식별자·본문 좌표·버전 처리 규칙이다. 기존 V1·V3·V5·V6와 테이블 정의서의 결정에 맞추며, 2026-11-06 사용자 확인으로 텍스트 offset의 기준을 **독자에게 표시하는 텍스트**로 확정했다. 태그를 포함한 원본 문자열은 좌표로 사용하지 않는다.

이 문서는 후속 구현의 논리 데이터 계약이다. 아래 예시 필드가 현재 API에서 이미 반환된다는 뜻은 아니다. HTTP 경로·인증·오류 응답은 관련 구현 이슈에서 OpenAPI에 반영한다. 기존 `/works/{slug}`는 목차 메타데이터만 제공하며 본문을 반환하지 않는다. 기존 API·DB를 이 문서만으로 변경하지 않는다.

## 1. 식별자와 콘텐츠 관계

| 대상 | 공통 식별 규칙 | 기존 저장/전달 값 |
| --- | --- | --- |
| 작품 | 외부 `workId`는 문자열 slug | 홈/상세의 `id`; DB `book.id` 숫자와 구분 |
| 콘텐츠 종류 | `book`, `novel`, `magazine` | DB `BOOK`, `WEBNOVEL`, `MAGAZINE` |
| 매거진 호 | 호 하나가 독립된 book 한 행·독립 slug | `volume_label`은 표시 문구이며 식별자로 사용하지 않음 |
| 회차/장/아티클 | `chapterId`는 chapter.id의 10진 문자열 | 현재 상세 응답 `contents[].id`와 같음. 숫자로 강제 변환하지 않음 |
| 회차 순서 | `chapter_no` 오름차순 | ID의 대소·배열 index를 회차 번호로 쓰지 않음. 번호에 빈 구간이 있어도 인접한 공개 회차로 이동 |
| 본문 | 회차별 `content_url` + `content_version` | 원본 파일과 뷰어용 본문 변환 결과의 연결을 서버가 관리 |
| 본문 구간 | 작품·회차·본문 버전 + offset/range | HTML DOM 경로·화면 px·앱 계산 쪽수는 저장 좌표가 아님 |
| 이미지/영상/음원 | `chapter_media.id`의 문자열을 `mediaId`로 전달 | 같은 작품·회차의 media만 연결; `sort_order`는 배치 순서이지 ID가 아님 |
| Canvas | 본문 콘텐츠가 정의한 상호작용 | V6 media type은 IMAGE/VIDEO/AUDIO이며 CANVAS 값을 임의로 넣지 않음 |

작품·회차·미디어의 소속은 서버에서 검증한다. 회차 참조의 `(chapter_id, book_id)` 복합 FK를 유지한다. 회원 데이터의 소유자는 인증된 세션에서 구하고 클라이언트의 memberId를 신뢰하지 않는다. 초안·숨김 작품 및 아직 공개되지 않은 회차의 본문·미디어·요약은 독자 응답에서 제외한다.

## 2. 텍스트 본문과 기준 문자열

`book`·`novel`의 저장 좌표는 서버가 제공하는 **기준 텍스트(canonical text)**의 UTF-16 코드 단위다. 원본 HTML/EPUB 등의 지원 포맷은 업로드/변환 작업(#25)에서 정하되, 동일 회차·동일 contentVersion의 기준 텍스트는 모든 플랫폼에서 동일해야 한다.

기준 텍스트 생성은 다음 순서로 한 번만 수행한다.

1. 지원 포맷 파서로 본문 읽기 순서를 결정한다. 제목·목차·지난 이야기·버튼/이미지 설명처럼 본문과 별도로 표시하는 UI 문자열은 제외한다. 이미지·영상·Canvas 자체도 글자 수에 넣지 않는다.
2. 서식 태그·실행 코드·스타일·설정집 링크 문법을 제거하고 표시할 문자열을 얻는다. `[[42|달빛 공방]]`은 `달빛 공방`만 남긴다. HTML은 정규식으로 모든 태그를 지우는 방식 대신 포맷 파서를 사용하고 문자 참조를 해석한다.
3. 문단 경계는 LF 2개(`\n\n`), 문단 내 명시적 줄바꿈은 LF 1개(`\n`)로 표현한다. CRLF/CR은 LF로 통일한다. UTF-8 BOM은 파일 시작에서만 제거한다. 포맷이 정의한 공백 처리는 변환기가 결정하고 결과에 보존한다. Unicode NFC/NFD 변환이나 전체 trim은 추가로 하지 않는다.
4. 이 결과를 버전별 기준 텍스트로 고정하고 길이를 chapter.char_count와 일치시킨다. 변환·스팬 생성 뒤 앱에서 재정규화/trim/태그 제거를 반복하지 않는다. `file_format` 표시 문자열만으로 렌더링 포맷을 추정하지 않는다.

서식·설정집 링크가 필요하면 기준 텍스트의 `[startOffset, endOffset)` 주석으로 전달한다. 서버와 앱은 같은 기준 문자열을 공유하며 원본 HTML 위치를 독서 좌표로 저장하지 않는다. 미개방·삭제된 설정집 주석은 링크 없이 본문 글자만 표시하고 제한된 항목 정보를 응답에 섞지 않는다. 주석이 켜지거나 꺼져도 기준 문자열과 offset은 바뀌지 않는다.

### 좌표와 검증

- 점 위치: `0 ≤ offset ≤ charCount`. 0은 회차 시작, charCount는 회차 끝이다. 정수만 허용한다.
- 하이라이트: `0 ≤ startOffset < endOffset ≤ charCount`, 끝은 포함하지 않는다.
- offset은 UTF-16 서로게이트 쌍 중간에 놓일 수 없다. 글자 선택은 뷰어에서 결합 문자/이모지를 온전히 선택하도록 하되 저장 단위는 UTF-16을 유지한다.
- 본문 버전과 길이가 확인되지 않은 위치를 정상 저장으로 처리하지 않는다. 잘못된 요청을 범위 안으로 몰래 잘라 저장하지 않는다.
- `A😀B`의 길이는 4다. 😀의 구간은 `[1,3)`, 회차 끝은 4이고 offset 2는 거부한다.
- `<b>이안</b>이 돌아왔다.`의 기준 텍스트는 `이안이 돌아왔다.`다. 이안은 `[0,2)`이며 굵게 표시하는 태그의 길이는 세지 않는다.

## 3. 매거진·고정 레이아웃 좌표

매거진의 기본 독서 위치는 **호 전체의 1부터 시작하는 쪽 번호**다. 기사별 1쪽 재시작이나 화면 비율·화면 픽셀을 저장하지 않는다.

- 아티클의 범위는 `[start_page, 다음 아티클 start_page - 1]`, 마지막 아티클은 page_count까지다. 회차 순서는 chapter_no이며 start_page는 그 순서로 엄격히 증가해야 한다.
- 한 쪽의 chapterId는 해당 쪽을 포함하는 아티클이다. 다른 아티클의 chapterId와 쪽 번호를 섞은 요청은 거부한다.
- page_count가 없으면 기존 정의서대로 마지막 아티클의 상한 검증은 보류하며 전체 진행률은 제공하지 않는다. 이를 100%나 page_count=0으로 대체하지 않는다. 아티클 하한·정수 검사는 유지한다.
- 현재 스키마로 보존하는 고정 레이아웃 하이라이트는 **쪽 범위 표식**이다. start_offset·end_offset은 양쪽 끝을 포함하는 쪽 번호이며 같으면 한 쪽이다. 텍스트의 끝 제외 범위와 혼합하지 않는다. 여러 아티클을 가로지르면 아티클별 기록으로 나눈다.
- FE6의 쪽 안 문장·사각 영역 좌표 및 PDF 문자 선택은 이번 기본 좌표와 분리한 후속 계약이다. 현재 컬럼에 임의 픽셀이나 텍스트 offset을 넣어 정밀 하이라이트 완료로 표현하지 않는다. `snippet`에는 실제 선택 텍스트가 있을 때만 넣고, 쪽 번호를 문장으로 꾸미지 않는다.
- 이미지 확대·회전·글꼴/테마 변경과 재생 진행은 기본 독서 위치를 변경하지 않는다. mediaId와 재생 초를 독서 offset으로 저장하지 않는다. 미디어의 배치 지점이 필요하면 동일 버전 텍스트 경계나 쪽 번호를 참조하고 상세 포맷은 #41~43에서 정의한다.

## 4. 논리 전달 형식

필드 역할을 합의하기 위한 예시다. 신규 HTTP 엔드포인트나 저장 컬럼이 이미 있다는 뜻은 아니다. `unit`은 content_type으로 파생할 수 있으며 DB 컬럼 추가를 요구하지 않는다. `contractVersion`과 회차 본문 `contentVersion`은 서로 다르다.

텍스트 회차 예시:

```json
{
  "contractVersion": 1,
  "workId": "sample-novel",
  "kind": "novel",
  "chapter": { "id": "501", "number": 2, "title": "귀환", "contentVersion": 3 },
  "body": { "type": "text", "text": "A😀B", "charCount": 4 },
  "position": { "chapterId": "501", "offset": 3, "unit": "utf16", "contentVersion": 3 }
}
```

매거진 위치 예시:

```json
{
  "contractVersion": 1,
  "workId": "orbit-2026-11",
  "kind": "magazine",
  "chapter": { "id": "902", "number": 2, "title": "밤하늘", "contentVersion": 1 },
  "body": { "type": "pages", "startPage": 5, "endPage": 8, "pageCount": 10 },
  "position": { "chapterId": "902", "offset": 6, "unit": "page", "contentVersion": 1 }
}
```

본문·미디어 파일 자체는 별도 조회로 받을 수 있다. 어느 전송 형태든 같은 식별자·버전·기준 문자열·쪽 범위를 충족해야 한다. `body.type=pages` 예시는 이미지/PDF 등의 실제 파일 목록 포맷을 대신하지 않는다. URL은 콘텐츠 위치이며 기록 소유권이나 공개 권한을 대신하지 않는다. 비공개 원본을 영구 공개 정적 경로로 노출하지 않는 제공 방식은 #25·35에서 검증한다.

## 5. 마지막 위치·진행률·최고 도달 회차

| 값 | 의미 | 되돌아 읽을 때 |
| --- | --- | --- |
| 마지막 위치 | 마지막 정상 저장의 chapter_id + chapter_offset + content_version | 이전 회차로 이동할 수 있음 |
| 위치 기준 진행률 | 현재 공개 본문 중 마지막 위치의 상대 위치 | 감소할 수 있음. 실제 읽은 문장/시간의 비율이 아님 |
| 최고 도달 회차 | 실제 진도 저장으로 도달한 회차 중 chapter_no가 가장 큰 회차 | 뒤로 이동해도 감소하지 않음 |
| 회차별 읽음 표시 | 최고 도달 회차를 이용한 파생 표시 | 건너뛴 회차도 읽음으로 간주하는 현 단순화 규칙 유지 |
| 설정집 개방 범위 | 자동 최고 회차 또는 수동 limit_chapter_id | 수동 설정은 독서 위치·진행률을 갱신하지 않음 |

텍스트 회차 내 진행률은 `offset / charCount`다. 0글자 회차는 0으로 나누지 않고 산정 불가로 처리하며 그 값만으로 완독 처리하지 않는다. 작품 전체는 **현재 공개된 회차**의 charCount 합을 분모로 하고, 현재 회차 앞의 공개 회차 길이 합 + 현재 offset을 분자로 쓴다. 길이가 모두 검증된 같은 조회 시점 자료일 때만 계산한다. 공개되지 않은 회차 수·글자 수를 분모에 넣지 않는다.

매거진은 page_count가 검증된 경우 현재 쪽의 끝까지 도달한 위치 비율 `pageNumber / pageCount`를 쪽 기준 진행률로 사용한다. 쪽 단위 진행률이며 실제로 글을 읽었다는 판정은 아니다. 기존 앱 계산 텍스트 쪽수(24/186)는 저장하거나 이 분모로 사용하지 않는다.

진행률은 별도 DB 숫자로 중복 저장하지 않고 같은 버전의 위치와 콘텐츠 메타데이터로 파생한다. 위치 저장·last_read_at·서재 상태 전이는 한 트랜잭션에서 처리한다(DAR-001). 마지막 위치의 서버 저장 결과를 받은 뒤 UI에서 저장 완료로 표시한다. 실패하면 기존 저장본과 입력을 보존한다. 다중 기기 충돌의 동시성 정책은 #38에서 정하며 기기 시계만으로 최신 여부를 결정하지 않는다.

연재 회차가 추가되면 전체 진행률은 감소할 수 있다. 저장된 COMPLETED의 새 회차 표시 및 재독 시 READING 전이는 기존 정의서를 따른다. 열람 요청·설정집 조회만으로 진도를 올리지 않고 정상 독서 위치 저장과 구분한다. 최초 열람 위치는 첫 공개 회차의 0(텍스트) 또는 해당 시작 쪽(매거진)이다.

### 회차 건너뛰기·설정집 예시

1화(id=900, 100글자)·2화(id=101, 200글자)·3화(id=50, 300글자)가 공개돼 있다고 하자.

- 3화 offset 30 저장: 위치 기준 전체 진행률 `(100 + 200 + 30) / 600 = 55%`, 최고 회차는 id=50이다. 숫자가 가장 큰 id=900이 아니다.
- 다시 1화 offset 20 저장: 이어보기는 1화 20, 위치 기준 진행률은 약 3.33%, 최고 회차는 여전히 3화다.
- 별도 읽음 이력이 없는 현 모델은 3화까지 회차 단위로 도달한 것으로 간주한다. 2화 실제 정독 여부까지 증명하지 않는다. 건너뛰기 전에 설정집이 열릴 수 있다는 안내를 제공한다.
- 자동 설정집은 최고 도달 3화까지, 수동으로 1화를 선택하면 1화까지만 공개한다. 이때 독서 위치·최고 회차·진행률은 바뀌지 않는다. 자동 복귀는 수동 행을 제거한다.
- 기록이 전혀 없고 수동 범위도 없으면 자동 범위는 0회차다. 존재하지 않는 0번 회차를 FK로 저장하지 않는다. 기존 자료의 max_chapter_id만 NULL이면 현재 회차를 호환 기준으로 사용하고 정상 저장 때 최고 회차를 채운다.
- 설정집 공개는 회차 단위이므로 회차 안 offset과 무관하다. 공개 전 회차·숨김 작품은 자동/수동 어느 모드에서도 우회하지 못한다. 잠금 항목은 기존 V5 규칙대로 제한된 정보만 반환한다.

## 6. 본문 개정과 버전 불일치

- 기준 텍스트나 쪽·미디어 배치 등 좌표 해석이 바뀌면 content_version을 올린다. 같은 버전 URL의 내용을 조용히 바꿔 기존 offset을 무효화하지 않는다. 단순 스타일 변경으로 기준 문자열과 좌표가 같으면 본문 버전을 올릴 필요는 없다.
- 본문과 char_count·메타데이터는 같은 버전으로 제공한다. 앱은 본문을 받은 버전을 기록과 함께 전송하며 서버는 저장 시 현재 버전·소속·범위를 다시 검사한다.
- 구버전 저장을 최신 위치로 덮어쓰지 않는다. 결과는 ‘버전 변경/재확인 필요’로 구분한다. 실제 HTTP 상태 코드와 오류 스키마는 #38·39·40의 OpenAPI에서 정한다.
- 재진입 때 reading_progress에는 snippet 컬럼이 없으므로 자동 문장 복원을 보장하지 않는다. ‘본문이 수정되어 위치 확인이 필요해요’를 안내하고 해당 회차 시작을 복구 후보로 제공한다. 사용자 확인/실제 독서 전에는 기존 기록이나 최고 회차를 덮어쓰지 않는다.
- 북마크·하이라이트의 snippet은 최신 같은 회차에서 재탐색할 후보다. 유일하게 일치하는 완전한 문장이면 새 위치를 제안할 수 있지만, 후보 없음/중복/잘린 snippet이면 정확한 구간이라고 표시하지 않는다. 하이라이트가 500자를 넘어 잘린 경우 전체 끝 위치를 추측하지 않는다. 확인 전 구버전 데이터는 보존한다.
- 매거진 쪽 구성 변경도 버전 불일치로 다룬다. 텍스트 snippet 검색으로 PDF 쪽 위치가 자동 복원된다고 보장하지 않는다.
- 이미 참조되는 회차 ID는 재사용하지 않는다. 회차 순서 변경·호 전체 쪽 구성 재편은 기존 기록/최고 회차·설정집의 의미를 함께 재검증하는 별도 콘텐츠 개정으로 다룬다.

## 7. 공통 수용 예시와 후속 작업

| 검증 | 예상 결과 |
| --- | --- |
| 굵은 글자 태그·설정집 문법 제거 | 표시 문자열 기준으로 좌표 생성, 서식/링크 토글 후 위치 동일 |
| A😀B의 offset 2 / [1,3) | 중간 점 위치 거부 / 😀 선택 성공 |
| 3화→1화 재독 | 마지막 위치는 1화, 최고 회차는 3화, 자동 설정집은 3화 유지 |
| 수동 범위 축소·자동 복귀 | 독서 위치 불변, 범위만 변경, 자동 복귀 시 수동 행 제거 |
| 다른 작품의 chapter/media 참조 | 저장·조회 연결 거부 |
| 매거진 1~4쪽/5~8쪽/9~10쪽 | 6쪽은 두 번째 아티클, 같은 아티클 3쪽 요청 거부 |
| 매거진 단일 쪽 표식 [6,6] | 한 쪽 표식으로 유효, 텍스트 [6,6)은 빈 범위라 거부 |
| 본문 v3·저장 v2 | 성공으로 덮어쓰지 않음, 복구 안내, 기존 기록 보존 |
| 새 회차 추가 | 분모 재계산 가능, 아직 공개되지 않은 회차는 분모·목차·링크에서 제외 |

구현 담당자는 이 예시를 #35·38~40·49의 테스트로 옮긴다. API HTTP 경로·본문 파일 변환기/지원 포맷·Canvas 포맷·매거진 쪽 안 정밀 선택(FE6)·다중 기기 저장 충돌 구현은 해당 기능 이슈에서 확정/검증한다. 이 분리는 기본 식별자·좌표·읽음/개방 의미를 미정으로 되돌리는 것이 아니다.
