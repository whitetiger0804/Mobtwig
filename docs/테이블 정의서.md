# 테이블 정의서

MySQL 8.4 물리 설계입니다. 이 문서를 기준으로 `V1__create_member_and_content.sql`부터 `V6__create_media_and_community.sql`까지 Flyway 마이그레이션을 작성합니다. 설계를 바꿀 때는 이 문서를 먼저 고친 뒤 DDL에 반영합니다. `docs/ERD.drawio`의 개념 ERD(9/30)는 이 문서와 구조가 달라 이 문서를 기준으로 다시 그립니다.

## 공통 기준

| 항목 | 기준 |
| --- | --- |
| 이름 | 테이블·컬럼 모두 `snake_case` 단수형입니다. JPA 기본 네이밍 전략이 `camelCase` 필드를 이 형식으로 변환합니다. |
| PK | 모든 테이블이 `id BIGINT AUTO_INCREMENT`를 사용합니다. 연결 테이블도 같으며 중복은 UNIQUE 제약으로 막습니다. |
| FK | `{참조테이블}_id` 형식입니다. MySQL이 FK 컬럼에 인덱스를 자동으로 만듭니다. |
| 회차 참조 | 회차를 참조하는 테이블은 모두 `book_id`를 함께 두고 `(chapter_id, book_id)` → `chapter(id, book_id)` 복합 FK를 사용합니다. 기록이 가리키는 회차와 책이 서로 다른 작품이 되지 않도록 막습니다. |
| 독서 위치 | offset 단위는 아래 [독서 위치](#독서-위치-offset-단위)를 따릅니다. |
| 문자셋 | `utf8mb4` / `utf8mb4_0900_ai_ci`입니다. 비교가 대소문자를 구분하지 않으므로 이메일 UNIQUE도 대소문자 구분 없이 동작합니다. |
| 시각 | `TIMESTAMP`, UTC로 저장합니다. `created_at`은 `DEFAULT CURRENT_TIMESTAMP`, `updated_at`은 추가로 `ON UPDATE CURRENT_TIMESTAMP`를 사용합니다. `TIMESTAMP`는 2038-01-19까지 저장할 수 있으며, 날짜만 필요한 값은 `DATE`를 사용합니다. |
| 상태값 | `VARCHAR(20)` + `CHECK` 제약입니다. JPA에서는 `@Enumerated(EnumType.STRING)`으로 매핑합니다. 값 추가는 다음 버전 마이그레이션으로 CHECK를 바꿉니다. |
| 긴 텍스트 | 리뷰·댓글·메모처럼 화면에 글자 수 제한이 있는 입력은 `VARCHAR`, 소개처럼 긴 글은 `TEXT`를 사용합니다. |
| 삭제 정책 | 회원 행은 실제 삭제하지 않고 `status = 'WITHDRAWN'`으로 바꾼 뒤 익명화합니다. 탈퇴 시 개인 데이터는 삭제하고, 리뷰·글·댓글은 남기되 작성자를 익명으로 표시합니다. FK는 부모가 소유한 하위 데이터만 `ON DELETE CASCADE`, 나머지는 `RESTRICT`입니다. 자세한 내용은 [삭제 정책 요약](#삭제-정책-요약)을 따릅니다. |

### 독서 위치 (offset 단위)

독서 위치와 기록의 offset 단위는 `book.content_type`으로 정한다.

- 텍스트 콘텐츠(`WEBNOVEL`, `BOOK`): 해당 회차 본문 원문의 시작을 0으로 하는 **문자 offset**이다. 문자는 UTF-16 코드 단위(Java·JavaScript 문자열 길이와 같음)로 센다. `end_offset`은 포함하지 않는 끝 위치다. 범위는 `0 ≤ offset ≤ chapter.char_count`다.
- 고정 레이아웃(`MAGAZINE`): 호 전체를 기준으로 1부터 시작하는 **쪽 번호**다. `chapter_id`는 그 쪽이 속한 아티클(`start_page`가 그 쪽 이하인 마지막 회차)이다. 범위는 `chapter.start_page ≤ offset ≤ (다음 회차의 start_page − 1)`이고, 마지막 회차는 `book.page_count`까지다. `page_count`가 NULL이면 상한 검증을 건너뛴다(FE6 확정 전 잠정).
  - 매거진 chapter의 `start_page`는 NOT NULL이고 회차 순서대로 커진다(승인 요청 시 서비스 검증).
- 책장 넘기기의 쪽 수(예: 24/186)는 앱이 계산하며 저장하지 않는다. 글자 크기를 바꿔도 같은 문자 offset은 같은 위치를 가리킨다. 매거진 쪽 번호는 호 전체 기준이다.
- offset은 기록할 당시의 `chapter.content_version`을 기준으로 한다. 버전이 바뀌면 `snippet`으로 위치를 다시 찾는다.
- 단위가 다르므로 DB CHECK로 검증하지 않고, 서비스 계층에서 `content_type`별로 범위를 검사한다.
- 적용 컬럼: `reading_progress.chapter_offset`, `bookmark.chapter_offset`, `highlight.start_offset`·`end_offset`.

## 회원

### `member` · 회원

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT` | N | AUTO_INCREMENT | PK |
| `email` | `VARCHAR(255)` | N | | 로그인 이메일, UNIQUE. 로그인은 이메일·비밀번호 방식만 제공합니다. 가입할 때 도메인에 점(`.`)이 없는 이메일은 거부합니다(서비스 계층 검증). 탈퇴 회원 값 `withdrawn_{id}@invalid`와 겹치지 않게 하기 위함입니다. |
| `password_hash` | `VARCHAR(255)` | N | | BCrypt 등 해시 값. 평문은 저장하지 않습니다. |
| `nickname` | `VARCHAR(30)` | Y | | 화면 표시 이름, UNIQUE. 가입 시 입력받습니다. 탈퇴 시 NULL이며, UNIQUE는 NULL끼리 겹쳐도 허용합니다. |
| `role` | `VARCHAR(20)` | N | `'USER'` | `USER`, `ADMIN`. 콘텐츠 관리자 식별용 |
| `status` | `VARCHAR(20)` | N | `'ACTIVE'` | `ACTIVE`, `SUSPENDED`, `WITHDRAWN` |
| `withdrawn_at` | `TIMESTAMP` | Y | | 탈퇴 시각 |
| `created_at` | `TIMESTAMP` | N | `CURRENT_TIMESTAMP` | 가입일 |
| `updated_at` | `TIMESTAMP` | N | `CURRENT_TIMESTAMP` | 수정 시각 |

- UNIQUE: `uk_member_email(email)`, `uk_member_nickname(nickname)`
- CHECK: `role IN ('USER', 'ADMIN')`, `status IN ('ACTIVE', 'SUSPENDED', 'WITHDRAWN')`, `status <> 'WITHDRAWN' OR withdrawn_at IS NOT NULL`, `status = 'WITHDRAWN' OR nickname IS NOT NULL`
- 탈퇴 익명화 규칙: 한 트랜잭션에서 다음을 처리합니다.
  - `status = 'WITHDRAWN'`, `withdrawn_at = 현재 시각`
  - `email` → `withdrawn_{id}@invalid`, `nickname` → NULL. 같은 이메일·닉네임으로 다시 가입할 수 있고, 탈퇴 회원의 닉네임이 다른 회원의 닉네임과 충돌하지 않습니다.
  - `password_hash` → 로그인할 수 없는 임의 값
  - [삭제 정책 요약](#삭제-정책-요약)의 개인 데이터 삭제
  - 삭제하는 찜만큼 `book.wishlist_count`를 줄입니다([캐시 컬럼 갱신](#캐시-컬럼-갱신-v4)).
- 남은 리뷰·글·댓글·작품의 작성자는 DB 문자열이 아니라 `status = 'WITHDRAWN'`을 보고 앱이 "탈퇴한 회원"으로 표시합니다.

### `SPRING_SESSION`, `SPRING_SESSION_ATTRIBUTES` · 세션

세션은 Spring Session JDBC로 저장합니다. 두 테이블은 직접 설계하지 않고, 이 프로젝트가 쓰는 spring-session-jdbc 버전의 jar에 들어 있는 `schema-mysql.sql`과 같은 구조로 만듭니다. 대문자 이름은 [공통 기준](#공통-기준)의 이름 규칙에서 예외입니다.

기준: spring-session-jdbc 4.1.1 jar(Spring Boot 4.1.1 → spring-session-bom 4.1.1, 의존성 `spring-boot-starter-session-jdbc`)의 `org/springframework/session/jdbc/schema-mysql.sql`. 원문은 `ENGINE=InnoDB ROW_FORMAT=DYNAMIC`만 지정하고 문자셋·정렬을 지정하지 않으므로 DB 기본값(`utf8mb4`/`utf8mb4_0900_ai_ci`)을 따릅니다.

`SPRING_SESSION`

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `PRIMARY_ID` | `CHAR(36)` | N | | PK |
| `SESSION_ID` | `CHAR(36)` | N | | 세션 ID, UNIQUE |
| `CREATION_TIME` | `BIGINT` | N | | 생성 시각(epoch ms) |
| `LAST_ACCESS_TIME` | `BIGINT` | N | | 마지막 접근 시각(epoch ms) |
| `MAX_INACTIVE_INTERVAL` | `INT` | N | | 최대 비활성 시간(초) |
| `EXPIRY_TIME` | `BIGINT` | N | | 만료 시각(epoch ms) |
| `PRINCIPAL_NAME` | `VARCHAR(100)` | Y | | 로그인 사용자 이름 |

- PK: `SPRING_SESSION_PK(PRIMARY_ID)`
- UNIQUE: `SPRING_SESSION_IX1(SESSION_ID)`
- INDEX: `SPRING_SESSION_IX2(EXPIRY_TIME)`, `SPRING_SESSION_IX3(PRINCIPAL_NAME)`

`SPRING_SESSION_ATTRIBUTES`

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `SESSION_PRIMARY_ID` | `CHAR(36)` | N | | FK → `SPRING_SESSION.PRIMARY_ID` (CASCADE) |
| `ATTRIBUTE_NAME` | `VARCHAR(200)` | N | | 속성 이름 |
| `ATTRIBUTE_BYTES` | `BLOB` | N | | 직렬화한 속성 값 |

- PK: `SPRING_SESSION_ATTRIBUTES_PK(SESSION_PRIMARY_ID, ATTRIBUTE_NAME)`
- FK: `SPRING_SESSION_ATTRIBUTES_FK` → `SPRING_SESSION(PRIMARY_ID)` ON DELETE CASCADE
- 만료 세션은 Spring Session 정리 작업(`spring.session.jdbc.cleanup-cron`, 기본 1분마다)이 삭제합니다.
- 설정: `spring.session.jdbc.initialize-schema=never`. 테이블은 Spring Session이 만들지 않고 Flyway V2로 만듭니다.

작품 단위로 승인합니다.

#### 회차별 읽음 표시 (파생 규칙)

회차별 읽음 여부는 저장하지 않고 `reading_progress`에서 계산합니다. 회차별 읽음 테이블은 보류합니다.

- 회차 번호 < 위치 회차(`chapter_id`)의 번호 → 읽음
- 같은 회차 → 읽는 중(%). 비율은 `chapter_offset`과 `char_count`(매거진은 쪽 범위)로 앱이 계산합니다.
- 그 사이에서 건너뛴 회차는 `max_chapter_id`까지 읽음으로 처리합니다. `max_chapter_id`가 NULL이면 위치 회차만 기준으로 합니다.

#### `library_book.status` 전이

1. 회원이 회차를 처음 열면, 행이 없으면 `READING`으로 만들고 `WANT_TO_READ`이면 `READING`으로 바꾼다.
2. 마지막 회차의 끝(텍스트는 `char_count`, 매거진은 마지막 쪽)에 도달하면 `COMPLETED`로 바꾼다.
3. 자동 전이는 앞으로만 진행한다(`WANT_TO_READ` → `READING` → `COMPLETED`). 회원이 수동으로 뒤로 바꾼 상태는 회차를 다시 열면 앞으로 전이될 수 있다. 회원은 상태 시트에서 언제든 직접 바꿀 수 있다(시안 s3).
4. `COMPLETED`인 작품을 다시 읽어 위치가 저장되면 `READING`으로 바꾼다(확정). 마지막 회차의 끝에 다시 도달하면 `COMPLETED`로 바꾼다.
5. 자동 전이는 위치 저장과 같은 트랜잭션에서 처리한다(DAR-001).
6. "서재에서 빼기"는 `library_book` 행만 지운다. `reading_progress`·북마크·하이라이트는 남는다.
7. 연재 작품에 새 회차가 올라와 읽은 마지막 회차(`max_chapter_id`)가 최신 회차보다 앞서면, 화면에서 "읽는 중/새 회차"로 계산해 표시한다. 저장된 `status`는 바꾸지 않는다(확정).

| `snippet` | `VARCHAR(500)` | Y | | 하이라이트 범위의 앞 500자만 저장한다(위치 재탐색용). |
| `content_version` | `INT` | N | | 기록할 때의 `chapter.content_version` |
| `color` | `VARCHAR(20)` | N | `'YELLOW'` | 하이라이트 색. `YELLOW`, `GREEN`(10-31 확정, FE5) |
| `memo` | `VARCHAR(1000)` | Y | | 메모 |
| `created_at` | `TIMESTAMP` | N | `CURRENT_TIMESTAMP` | |
| `updated_at` | `TIMESTAMP` | N | `CURRENT_TIMESTAMP` | |

- UNIQUE: `uk_highlight_member_range(member_id, chapter_id, start_offset, end_offset)`
- FK: `fk_highlight_chapter(chapter_id, book_id)` → `chapter(id, book_id)`
- CHECK: `start_offset >= 0`, `end_offset >= start_offset`, `content_version >= 1`, `color IN ('YELLOW', 'GREEN')`. 텍스트에서 빈 범위(`end_offset = start_offset`)는 서비스 계층에서 막습니다.
- INDEX: `idx_highlight_member_book(member_id, book_id, created_at)` — 작품별 내 기록
- `snippet`(북마크 200자, 하이라이트 500자)을 UTF-16 기준으로 자를 때 서로게이트 쌍(이모지 등) 중간에서 자르지 않는다(서비스 계층). 중간에서 자르면 오류 없이 남은 반쪽이 `?`로 바뀌어 저장된다(Connector/J 9.7.0으로 확인).
- 삭제: 회원이 지우면 행을 실제 삭제합니다.

## 리뷰·통계 (V4)

SFR-005·012·013, 시안 s1 도서 상세, s2 리뷰 작성·리뷰 댓글, s4 인기 목록을 반영합니다. 모든 FK는 RESTRICT입니다. 리뷰는 soft delete, 리뷰 댓글은 실제 삭제합니다([삭제 정책 요약](#삭제-정책-요약)).

### `review` · 리뷰

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT` | N | AUTO_INCREMENT | PK |
| `book_id` | `BIGINT` | N | | FK → `book.id` (RESTRICT) |
| `member_id` | `BIGINT` | N | | FK → `member.id` (RESTRICT) |
| `rating` | `TINYINT` | N | | 평점 1~5 |
| `content` | `VARCHAR(1000)` | N | | 본문. 시안 s2 "38 / 1000" (V4 변경: `TEXT` → `VARCHAR(1000)`) |
| `created_at` | `TIMESTAMP` | N | `CURRENT_TIMESTAMP` | 작성 시각 |
| `updated_at` | `TIMESTAMP` | N | `CURRENT_TIMESTAMP` | 수정 시각 |
| `deleted_at` | `TIMESTAMP` | Y | | 삭제 시각. NULL이면 삭제되지 않은 리뷰입니다. |
| `active_key` | `TINYINT` | Y | 생성 컬럼 | `GENERATED ALWAYS AS (IF(deleted_at IS NULL, 1, NULL)) STORED`. 중복 방지 UNIQUE에만 씁니다. |

- UNIQUE: `uk_review_book_member_active(book_id, member_id, active_key)` — 삭제되지 않은 리뷰는 회원별 책당 1건
- CHECK: `ck_review_rating`(`rating BETWEEN 1 AND 5`), `ck_review_content`(`CHAR_LENGTH(TRIM(content)) >= 1`)
- INDEX: `idx_review_book_created(book_id, created_at)` — 작품별 리뷰 목록(최신순)
- `link_url`은 시안 s2 리뷰 작성에 링크 입력이 없어 뺐습니다.
- soft delete와 재작성
  - 삭제는 `deleted_at`에 현재 시각을 넣습니다. `content`·`rating`은 지우지 않고 화면에만 보이지 않게 합니다.
  - 삭제된 행은 `active_key`가 NULL입니다. MySQL UNIQUE는 NULL끼리 겹쳐도 허용하므로, 같은 회원이 같은 책에 리뷰를 다시 쓰면 새 행으로 INSERT됩니다. 삭제된 리뷰의 댓글은 새 리뷰로 옮겨 가지 않습니다.
  - 생성식에 FK 컬럼(`member_id`)을 넣지 않습니다. MySQL은 저장 생성 컬럼의 기반 컬럼에 걸린 FK에 CASCADE·SET NULL을 허용하지 않기 때문입니다.
  - JPA 엔티티는 `active_key`를 매핑하지 않습니다. 조회 조건에는 `deleted_at IS NULL`을 씁니다.
- 본문은 필수입니다. 별점만 남기는 리뷰는 받지 않습니다(A13 임시값). 시안 s1 "내 별점 남기기"는 별점을 고른 채로 리뷰 작성 화면(s2)을 여는 동작으로 봅니다. 줄바꿈만 있는 본문은 서비스에서 trim한 뒤 막습니다.
- 글자 수: 앱은 UTF-16 단위로 1000자를 세고, `VARCHAR(1000)`은 문자(코드 포인트) 단위로 셉니다. 앱 제한이 같거나 더 엄격하므로 앱에서 통과한 입력을 DB가 거부하지 않습니다.
- 탈퇴한 회원의 리뷰는 익명으로 남고 평균 평점과 리뷰 수에도 계속 반영합니다(A13).
- 점수별 분포(UI-F-001)는 `deleted_at IS NULL`인 행을 `GROUP BY rating`으로 계산하며 캐시하지 않습니다.

- INDEX: `idx_review_comment_review_created(review_id, created_at)` — 리뷰별 댓글 목록과 댓글 수. 댓글 수는 캐시하지 않습니다.

  - 리뷰를 soft delete해도 댓글은 남고, 원문 자리에 "삭제된 리뷰입니다"를 표시합니다.
  - 삭제된 리뷰에는 새 댓글을 달 수 없습니다(서비스 계층 검증). 남은 댓글의 본인 수정·삭제는 할 수 있습니다.
  - 리뷰 목록에는 댓글이 1개 이상 남은 삭제 리뷰만 자리 표시로 보여 줍니다(임시값, 프론트 확인 필요).

### `book_stat_daily` · 일별 통계

인기 목록(SFR-005, 시안 s4 "지금 인기 있는 작품", UI-B-002·004 일간·주간 순위)에 씁니다. 순위 기준이 조회 수뿐이므로 조회 수만 저장합니다.

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT` | N | AUTO_INCREMENT | PK |
| `book_id` | `BIGINT` | N | | FK → `book.id` (RESTRICT) |
| `stat_date` | `DATE` | N | | 집계 날짜. 한국 시간(KST) 기준 날짜를 앱이 계산해 넣습니다. |
| `view_count` | `INT` | N | `0` | 그날의 작품 상세 조회 수 |

- UNIQUE: `uk_book_stat_daily_book_date(book_id, stat_date)`
- CHECK: `ck_book_stat_daily_view_count`(`view_count >= 0`)
- INDEX: `idx_book_stat_daily_date_view(stat_date, view_count)` — 일간·주간 순위. 주간 합산에서 `book_id`를 다시 읽는지 I3 EXPLAIN으로 확인합니다.
- 채우는 방식: 작품 상세 조회를 처리할 때 `INSERT … ON DUPLICATE KEY UPDATE view_count = view_count + 1`로 바로 반영합니다. 별도 로그 테이블이나 배치 집계는 없습니다.
- 기간: 일간은 오늘(KST) 행, 주간은 오늘을 포함한 최근 7일 행의 `SUM(view_count)`입니다. 장르·작품 종류 필터는 `book`, `book_genre`와 조인합니다.
- 오래된 행은 지우지 않습니다(작품당 하루 1행).
- 공통 기준의 UTC 규칙은 `TIMESTAMP`에 적용되며, 이 `DATE` 값은 KST 날짜 그대로 저장합니다.

### 캐시 컬럼 갱신 (V4)

`book`의 캐시 컬럼은 아래 동작에서만 바뀝니다. 캐시와 실제 집계(`COUNT`, `AVG`)가 맞는지는 점검 SQL로 확인합니다.

| 캐시 | 갱신 동작 | 트랜잭션 | 동시성 처리 |
| --- | --- | --- | --- |
| `average_rating`, `review_count` | 리뷰 작성, 별점을 바꾸는 수정, 리뷰 삭제(soft delete). 본문만 고치면 갱신하지 않습니다. 회원 탈퇴는 리뷰가 남으므로 갱신하지 않습니다. | 리뷰 변경과 같은 트랜잭션 | 트랜잭션 처음에 `SELECT id FROM book WHERE id = ? FOR UPDATE`로 작품 행을 잠근 뒤 리뷰를 바꿉니다. 그다음 `deleted_at IS NULL`인 리뷰로 `COUNT(*)`와 `ROUND(AVG(rating), 2)`(없으면 0.00)를 다시 계산해 UPDATE합니다. 같은 작품의 리뷰 쓰기는 차례로 처리되며, 증감이 아니라 재계산이므로 값이 어긋나도 다음 쓰기에서 맞춰집니다. |
| `view_count` | 작품 상세 조회 1회마다 +1. 비회원 포함, 중복 제한 없음(임시, 새로고침으로 증가 가능, 후속 과제) | 조회 응답과 별개의 짧은 트랜잭션. 같은 트랜잭션에서 `book_stat_daily`도 upsert합니다. 실패해도 상세 화면은 정상 응답합니다. | `UPDATE book SET view_count = view_count + 1 WHERE id = ?` 한 문장으로 처리합니다. 앱에서 값을 읽고 더해 쓰지 않습니다. |
| `recommend_count` | 없음(보류). 시안·요구사항에 추천 버튼과 추천 수 표시가 없습니다. 시안의 "추천"은 찜 기반 개인화 목록이며 이 컬럼과 관계없습니다. | — | A1 답을 받으면 V7 이후에 컬럼을 제거하거나 기능을 추가합니다. 그전까지 값은 0입니다. |
| `wishlist_count` | 찜 추가·해제, 회원 탈퇴 시 찜 삭제 | `wishlist` 변경과 같은 트랜잭션(V3 확정) | INSERT·DELETE가 실제로 1행을 바꿨을 때만 `wishlist_count = wishlist_count ± 1`을 실행합니다. `uk_wishlist_member_book` 때문에 두 번 눌러도 두 번 늘지 않습니다. 탈퇴 트랜잭션에서는 지운 찜의 작품별 개수만큼 줄입니다. |

## 추가 기능 후보 (후속 마이그레이션)

제안서·이슈 #10·디자인 시안(#3)에 나왔지만 팀에서 구현 범위를 확정하지 않은 기능입니다. 범위가 확정되면 이 초안을 위의 상세 표 형식으로 옮기고 V7 이후 마이그레이션으로 추가합니다. 컬럼은 `id`, `created_at` 등 공통 컬럼을 생략했습니다.

| --- | --- | --- | --- | --- |

| 높음 | 독서 통계·챌린지 | 시안 v2 ⑤⑦, 마이페이지 "이번 달 3권 읽음" | `reading_session`(member_id, book_id, started_at, ended_at), `reading_goal`(member_id, period, target_count) | 읽은 시간·하루 평균·연속 독서일은 `reading_session` 집계로 계산합니다. 완독 권수는 `library_book.status = 'COMPLETED'`로 셉니다. 배지까지 하면 `badge`, `member_badge`를 추가합니다. |

## 이후 반영 예정
- 각 버전: 조회 패턴에 맞춘 인덱스를 해당 버전 마이그레이션에 함께 넣습니다.
- 검색: 제목·출판사·저자명은 ngram FULLTEXT(V1)로 검색합니다. 1글자 검색 처리 방식(`LIKE` 병행 여부)은 확인 필요입니다.
- 기능 범위 확정 후: 위 추가 기능 후보를 상세 설계로 옮겨 V7 이후 마이그레이션으로 추가합니다.
