## 광고판 경계 순환·커뮤니티 상단 정리 · 명세 v0.16 · 2026-10-26

HTML 앱 미리보기와 Expo의 광고판 양쪽을 경계 복제 화면 방식으로 변경했다. 마지막에서 다음으로 이동하면 바로 옆 첫 배너까지 한 장만 진행하고, 첫 번째에서 이전으로 이동해도 마지막 배너까지 한 장만 되돌아간다. 정착 후 같은 내용의 원본 위치로 애니메이션 없이 재배치하며 이때 웹 스냅을 잠깐 해제한다. 원본 개수와 논리적 위치만 카운터에 표시하고 복제본은 접근성/탭 탐색에서 제외한다. 웹 화살표는 양쪽 경계에서도 활성화되며 단일 배너에서는 비활성화된다. 앱 모드에서는 기존대로 화살표를 숨긴다.

5초 시연 기본값·사용자 정지/재개·reduced motion 기본 정지·조작/포커스/팝업/백그라운드/이탈 정지와 새 간격 재개를 유지한다. 빠른 버튼 입력은 대기열에서 순서대로 처리하고, 유형/크기 변경과 이탈 시 이동 상태/대기 작업을 정리한다. Expo 웹에서 배너 위의 세로 휠은 페이지 스크롤로 전달하여 순환 배너 안에 갇히지 않게 했다. 빈/단일 배너는 복제본이나 자동 타이머를 만들지 않는다.

커뮤니티의 공통 화면 함수에서 반복 삽입하던 본인 사진·이름·프로필 편집 영역을 제거했다. 해당 래퍼와 전용 여백 스타일도 제거하여 홈·게시판 찾기·게시판·글 상세·글쓰기 모두 본문부터 시작한다. 공통 헤더의 작은 프로필 버튼, 마이페이지의 편집과 저장 데이터, 글/댓글 작성자 이름은 유지한다. Expo는 현재 커뮤니티 준비 화면이며 이 중복 영역이 원래 없어 제거할 코드가 없음을 확인했다. Expo에 HTML 커뮤니티 전체나 프로필 편집을 이식한 것은 아니다.

검증 기록: `.review-requirements/infinite-banner-tests.cjs`와 `infinite-banner-motion-traces.json`에 Chrome의 실제 프레임별 스크롤 위치를 남겼다. HTML/Expo 웹 실행본 각각 화살표·터치 양방향 8회와 자동 경계 2회에서 애니메이션 이동 거리는 +1 또는 -1장이고, 같은 화면으로의 비표시 재배치만 ±3장이었다. 빠른 연속 입력·키보드·원본만 접근성 노출·유형 전환·360/390/430px 크기 변경·앱 화살표 숨김·세로 휠 공존도 검사한다. 전체 단위 테스트 56개와 타입 검사 통과. 기존 자동 전환/스크롤바 회귀 검사에서 실제 기본 5초, 조작·포커스·팝업·숨김·이탈/복귀, reduced motion, 단일/빈 목록과 타이머 중복 방지를 확인했다. Expo 웹 번들을 최신 소스에서 다시 생성했다. Android/iOS 실기기에서 관찰한 결과는 아니며 로컬 기능 수정으로 배포/GitHub 업로드는 수행하지 않는다.


## 현재 HTML 커뮤니티 구현 상태 · 2026-10-26

아래 v0.13 문서 이관/준비 화면 설명은 구현 전의 기록이다. 현재 HTML에는 작품별·주제별 게시판, 작품/작가 검색과 빈 상태, 게시판별 검색·말머리·즐겨찾기, 글 상세/작성·계정별 초안, 별도 홍보 게시판과 연결 작품 소개, 기존 리뷰와 분리된 댓글을 구현했다. 일반 이미지는 본문만 최대 3장, PNG/JPEG/WebP 원본 2MiB 이하·긴 변 1024px 이하로 변환하며 대표이미지 한 장을 선택한다. 이미지 이모티콘은 자체 SVG 4종을 본문 최대 8개/댓글 최대 4개 선택한다. 댓글에는 일반 파일 첨부나 URL 이미지 임베드 경로가 없다. 이 수치와 중앙 표시·대표 선택 방식은 D-16~19의 시연 정책이다.

스포일러 글은 제목·미리보기·대표이미지·본문·이모티콘을 함께 가리고 댓글은 별도로 확인을 받는다. 확인은 회원/항목별이며 독서 진도나 설정집 수동 범위를 동의로 사용하지 않는다. 공유 게시물은 브라우저 로컬 `mobtwig-community-v1`, 즐겨찾기·초안·동의는 `mobtwig-community-profile-v1:<회원 ID>`에 저장한다. 계정당 저장 초안 하나, 명시적 임시저장 방식이며 저장 실패 시 입력과 기존 저장본을 유지한다. 실제 차단/운영 효과·서버 권한을 구현한 것은 아니다.

Figma B안의 design context와 screenshot 조회는 Starter 요금제 호출 제한으로 받지 못해 최신 확정 명세와 기존 HTML 스타일을 사용했다. Figma와 픽셀 일치를 확인했다고 주장하지 않는다. `community-assets/`는 외부 요청 없는 자체 이미지 자산이다. 커뮤니티/프로필/비공개 메모 브라우저 검증은 기존 리뷰·독서 데이터 보존과 계정 분리까지 포함한다. Expo 커뮤니티는 여전히 별도의 준비 화면이다.

## 프로필 편집 · SFR-034 / UI-H-005 · 2026-10-26

최신 명세 v0.15의 프로필 편집을 HTML 앱 미리보기에 구현했다. **마이페이지 → 프로필 편집**에서 닉네임과 이미지 선택·미리보기·저장·기본 이미지 복원·취소를 제공한다. 공통 헤더의 원형 프로필은 마이페이지 직접 이동을 유지한다. 저장한 이름·이미지는 마이페이지, 계정 설정, 공통 헤더(커뮤니티 화면 포함)에 반영된다. 커뮤니티 본문 안의 반복 계정 요약 영역은 최신 사용자 요청으로 제거했다. 새 커뮤니티 글·댓글은 저장한 이름을 사용한다.

저장 키는 `mobtwig-account-profile-v1:<encodeURIComponent(회원 ID)>`이며 `profile-editor.js`가 담당한다. 기존 계정 ID·서재·찜·진도·기록·차단 메모·글/댓글 소유권을 변경하지 않는다. 다른 회원 설정과 분리하며 재실행·기본 시연 계정 재로그인에도 복원한다. 신규 가입 계정의 재로그인 제한은 기존 가상 인증 설명과 동일하다. 공백 이름 거부·일반 텍스트 표시, 저장 실패 시 기존 저장본/편집 입력 보존, 이미지 읽기 실패 시 이전 선택/닉네임 보존, 손상 자료를 덮어쓰지 않는 오류/다시 읽기를 제공한다. 편집 중 화면이나 계정이 바뀌면 이전 이미지 읽기 결과를 적용하지 않는다. 취소하면 편집을 버리고 기존 저장 프로필을 유지한다.

**D-21 시연 정책:** 닉네임 앞뒤 공백 제거·최대 30 유니코드 코드포인트·중복 허용·변경 주기 제한 없음. 금칙어 정책은 구현/확정하지 않는다. PNG/JPEG/WebP 원본 2MiB 이하, 해상도 최대 2,400만 픽셀, 긴 변 최대 512px로 축소하여 PNG로 브라우저 내 변환, 변환 데이터 URL 최대 700,000자. 원형 중앙 표시로 미리보기하며 사용자가 직접 자르는 도구는 없다. 기본 이미지 복원은 저장해야 반영된다. 과거 게시글·댓글·기존 리뷰의 작성자 이름은 작성 당시 값을 유지하고 과거 사진 갱신/작가 필명 분리는 구현하지 않는다. 이 선택을 정식 정책으로 확정하지 않는다.

구현 범위는 `client/app-prototype` HTML이며 Expo·기존 `client/prototype`·서버를 변경하지 않았다. 실제 이미지 업로드·인증/인가·서버 저장, 비밀번호 변경·탈퇴·도전과제, GitHub 업로드·배포 완료를 뜻하지 않는다. 실제 프로필 편집은 비공개 메모의 가상 대상 이름 변경 도구와 별개다.

검증: 전체 단위 테스트 54개 통과(프로필 신규 4개 포함). `.review-requirements/profile-browser-tests.cjs`로 실제 Chrome HTML에서 진입·안전한 이름·이미지 선택/읽기 실패·저장 실패와 재시도·취소/복원·공통 표시·재실행/재로그인·회원 분리·기존 데이터/메모/소유 ID 보존·새 글 작성자 이름과 과거 이름 유지 및 360/390/430px의 가로 넘침/스크롤바 숨김을 확인했다. 390px 화면 이미지도 시각 검사했다. 네이티브 실기기 검증은 아니다.

참고: 2026-10-26 [노벨피아 공개 페이지](https://novelpia.com/)에서 개인 메뉴의 닉네임·로그인·내서재 구성을 읽기 전용으로 확인했다. 로그인 뒤 프로필 편집·이미지 규격·변경 정책은 확인하지 않았으며 타사 자산이나 정책을 복제하지 않았다. 프로필 편집 기능 범위는 Mobtwig v0.15를 따른다.


요구사항명세서 0.3과 UI설계서 1.0에서 시작해 아래 개정 사항을 반영한 브라우저용 프로토타입입니다. 기존 `client/prototype` 백과사전 시연은 보존합니다. Expo 앱은 별도 개발하며 이 HTML 시연은 React Native 앱에 연결된 구현이나 실제 서비스가 아닙니다.

## 실행

앱 크기 화면으로 시연하려면 **`app-preview.html`**을 여세요. 데스크톱에서는 휴대폰 프레임 안에서 동일한 프로토타입이 실행되며, 작은 화면·기본 화면·큰 화면을 선택할 수 있습니다. 실제 모바일에서는 프레임을 숨기고 화면 전체를 사용합니다. 기존 PC형 화면은 `index.html`에서 계속 확인할 수 있습니다. 앱 미리보기는 HTML 기반 모바일 화면 시연이며 React Native 빌드 결과는 아닙니다.

이 폴더 전체를 내려받아 `index.html`을 Chrome 또는 Edge에서 엽니다. 패키지 설치와 빌드가 필요 없으며 외부 폰트나 이미지 요청 없이 동작합니다. 콘텐츠 관리 시연은 같은 폴더의 `admin.html`을 엽니다.

원한다면 이 폴더에서 로컬 웹 서버를 실행해 모바일 화면 크기로도 확인할 수 있습니다. 로컬 주소를 다른 팀원의 기기에 전달하는 것만으로는 접속할 수 없으므로, 팀 공유에는 폴더 전체 또는 압축 파일을 전달하세요.

초기 화면은 `민서` 시연 계정으로 로그인되어 있습니다. 계정 설정에서 로그아웃한 뒤 아래 계정으로 로그인 동작을 확인할 수 있습니다.

- 계정 `reader@mobtwig.demo`
- 비밀번호 `demo1234`

이는 공개된 가상 시연 정보입니다. 실제 인증 API를 호출하지 않으며 실제 비밀번호나 개인정보를 입력하지 마세요. 신규 가입은 이번 실행 중의 인증 정보를 메모리에 보관하는 시뮬레이션입니다. 새로고침 후에는 기존 로그인 상태를 유지할 수 있지만, 신규 계정으로 다시 로그인하는 서버 기능은 제공하지 않습니다. 기본 시연 계정은 계속 사용할 수 있습니다.

## 추천 시연 순서

1. 홈에서 읽던 작품의 **이어 읽기**를 눌러 저장된 2화 2페이지로 이동합니다.
2. 본문의 밑줄 용어 **공명**을 눌러 설정 설명을 확인합니다.
3. 상단 **설정집**을 열고 분류·세부 분류·검색을 사용합니다. 아직 읽지 않은 인물의 이름은 검색되지 않습니다.
4. 회차 목록으로 돌아가 3화를 읽으면 해당 위치에서 공개되는 인물이 설정집에 나타납니다.
5. **읽기 설정**에서 글자 크기 5단계, 배경 4종, 책장 넘기기·스크롤, 애니메이션·효과음을 선택합니다. 다른 작품을 열어 같은 설정이 유지되는지 확인합니다.
6. 북마크를 추가하거나 본문 문장을 선택한 뒤 **선택한 문장 하이라이트**를 누릅니다. 마이페이지의 북마크·하이라이트에서 본문으로 돌아갑니다.
7. 작품 상세에서 찜·서재 담기·링크 복사와 리뷰 작성을 시연합니다. 본인 리뷰와 댓글은 수정·삭제할 수 있습니다.
8. `admin.html`에서 작품 정보와 첫 회차 본문을 초안으로 저장합니다. **앱북 게시**에서 검증 후 게시하면 같은 브라우저의 독자용 검색 목록에 추가됩니다.

## 저장과 시연 정책

- 시연 데이터는 `mobtwig-app-prototype-v1` 키로 현재 브라우저의 로컬 저장소에 보관합니다. 사용자가 달라지면 서재·설정·독서 위치·기록도 분리됩니다.
- 위치와 진행률은 하나의 저장 객체에 함께 기록합니다. 실제 DB 트랜잭션이나 서버 동시성 보장을 구현한 것은 아닙니다.
- 저장소를 사용할 수 없거나 저장 공간이 부족하면 안내하고 현재 실행 중의 데이터만 사용합니다.
- 설정집은 시연에서 **최대 도달 위치**를 개방 기준으로 사용합니다. 앞으로 이동한 회차는 열람한 것으로 취급합니다. 이는 미확정 정책 D-05를 위한 임시 선택이며 서비스 정책 확정이 아닙니다.
- 샘플 작품은 회차당 3페이지입니다. 텍스트 글자 크기가 바뀌어도 회차와 페이지 기준 위치를 유지합니다. 실제 리플로우 엔진의 정밀 위치 설계와 별개입니다.
- 샘플 요약은 직접 작성된 정적 문구입니다. 자동 요약 API를 사용하지 않습니다. 1화에는 이전 회차 요약이 없습니다.
- 첫 작품은 인물·개념·세계관을 포함한 설정집이 준비되어 있고 다른 작품은 빈 설정집을 보여줍니다. 관리 화면에서 다른 작품의 설정집 항목을 등록할 수 있습니다.
- 애니메이션과 효과음은 각각 켜고 끌 수 있습니다. 음성·영상 재생은 제공하지 않습니다. 효과음은 사용자 조작 때만 브라우저 오디오로 생성합니다.
- 리뷰를 삭제하면 연결된 시연 댓글도 함께 삭제합니다. 이 삭제 정책은 시연용이며 실제 서비스 정책은 별도 검토 대상입니다.
- 링크 복사는 같은 프로토타입 실행 환경의 작품 주소를 만듭니다. OS 공유 시트, 외부 앱 딥링크, 앱 미설치 웹 안내는 미정 범위라 구현하지 않습니다.
- 관리 화면은 권한 검증이 없는 독립된 **시연 화면**입니다. 실제 인증·인가, 파일 업로드·보안 검사, CDN 배포, 관리자 계정은 구현하지 않습니다. 텍스트 본문을 등록하고 그 결과를 독자 화면에서 확인합니다.
- 모든 작품·작가·표지·본문·계정·초기 리뷰는 가상 자료입니다. 표지는 SVG로 직접 구성했습니다.

## 설정집 개방 범위 설정

설정집 상단의 ‘개방 범위 설정’에서 자동(최고 도달 위치) 또는 직접 회차 끝까지 개방을 선택합니다. 아직 읽지 않은 범위는 스포일러 확인 체크 후 적용할 수 있습니다. 작품별·회원별로 저장되며 설정집 목록·검색·상세와 본문 용어 연결에 동일하게 적용합니다. 더 좁은 범위로 다시 잠그거나 자동으로 복귀할 수 있고 독서 위치·진행률은 변경하지 않습니다. 서버가 없는 시연이므로 실제 콘텐츠 보호를 보장하지 않습니다.

## 작품별 리뷰 제한

계정·작품별 현재 리뷰 1개만 허용하며 기존 작성자는 수정으로 연결합니다. 직접 주소에서도 기존 리뷰를 수정하고 등록 처리에서도 중복 요청을 거부합니다. 삭제 후 재작성은 가능합니다. 실제 서버의 유일성 제약과 다중 기기 동시성은 별도 구현 대상입니다.

홈 좌상단의 웹소설 버튼은 웹소설/모북이를 약 3초씩 교차 표시합니다. 버튼의 기능과 접근성 이름은 웹소설로 유지하며 레이아웃 폭은 고정합니다. 동작 줄이기 설정에서는 웹소설을 고정 표시합니다.

Genre strips support mouse drag and wheel scrolling as well as native touch scrolling. Dragging does not select a genre; clicking still applies the filter.

## 탐색 탭 콘티 업데이트 (2026년 10월 24일)

홈·탐색·내 서재·마이페이지의 헤더를 통합하여 검색·알림·프로필을 공통 제공합니다. 웹소설/일반도서 선택은 탭 간 유지하며 탐색·서재·찜 결과도 선택 유형으로 제한합니다. 일반도서는 연재 요일을 표시하지 않고 현재 일반도서의 분류를 사용합니다. 유형 변경 시 장르·요일·상태·회차 조건은 초기화합니다. 검색 팝업은 상단 카드로 열리며 입력칸과 검색 버튼 폭을 분리했습니다. 360/390/430px iframe에서 입력 폭·경계·작동을 확인했습니다.

## 홈 배너 터치와 가로 스크롤바 (2026년 10월 24일)

`home-banners.js`는 기존 홈 배너를 보완합니다. 손가락으로 좌우 스와이프하면 브라우저의 기본 가로 스크롤·스냅을 사용하며 세로 페이지 스크롤도 유지합니다. 드래그/스와이프는 작품 상세 탭으로 처리하지 않습니다. 짧은 탭·웹 화살표·키보드 좌우/Home/End는 사용할 수 있고 웹의 양끝 화살표는 비활성화합니다. 마우스 드래그도 지원합니다.

배너·장르·요일 가로 영역은 시각적 스크롤바를 숨깁니다. 스크롤 자체와 터치·휠·드래그·키보드 포커스 이동은 유지합니다. 이 절은 v0.10 당시 기록이며, v0.12부터 앱 모드는 세로 스크롤바도 숨기도록 확대했습니다. 실제 터치 입력으로 배너 스냅/오탭 방지/탭 상세/세로 스크롤을 확인했고, 요일 영역의 터치·휠·마우스 드래그·마지막 항목 포커스 이동과 360/390/430px 가로 넘침도 검증했습니다.

Expo 앱은 별도 `../src`에 개발되고 있습니다. 이 폴더의 이전 ‘Expo 기본 화면’ 설명과 구분하여 최신 앱 상태는 [기능 개발 상태](../FEATURES.md)를 확인하세요. 운영 서비스 참고 원칙은 프로젝트 `AGENTS.md`, 이번 확인 URL과 한계는 `FEATURES.md`에 기록했습니다.

## 광고판 표시와 커뮤니티 탭 (명세 v0.11)

광고판은 기존 공지/추천 배너의 임시 이름이며 실제 광고 연동을 뜻하지 않습니다. 일반 `index.html`은 화면 폭과 무관하게 웹으로 취급해 화살표를 유지합니다. `index.html?mode=app`은 앱 표시 모드로 화살표를 숨깁니다. `app-preview.html`은 PC의 iframe에서도 항상 이 모드를 전달하므로 앱 화면에 화살표가 나타나지 않습니다. 손가락 스와이프는 유지합니다.

광고판 아래 1/n 카운터는 현재 유형의 실제 배너 수와 위치를 표시하며 접근성 설명도 제공합니다. 스와이프·화살표·유형 전환·크기 변경을 반영하고 한 장은 1/1, 빈 목록은 광고판 영역을 숨깁니다. 위치 텍스트만 갱신하므로 화면 전체를 다시 그리거나 독서 기록을 변경하지 않습니다.

하단 순서는 홈·탐색·커뮤니티·마이페이지입니다. 커뮤니티는 공통 헤더와 준비 중 빈 화면뿐이며 게시판·글쓰기·댓글은 추가하지 않았습니다. 기존 서재·독서 기록·찜 데이터와 홈 및 마이페이지의 진입을 보존했습니다. 외부 미리보기 바로가기에는 커뮤니티를 반영하고 서재는 보조 바로가기로 유지합니다.

## 전체 스크롤바와 광고판 자동 전환 (명세 v0.12)

앱 모드에서는 가로뿐 아니라 세로·중첩 목록·팝업·설정집·입력 영역 및 app-preview.html 바깥 래퍼의 스크롤바도 시각적으로 숨깁니다. overflow:hidden으로 스크롤을 차단하지 않으며 실제 터치/휠/드래그/키보드 스크롤과 탭별 폭을 함께 검증합니다. 일반 index.html 웹 화면의 화살표·루트 스크롤바는 유지합니다.

광고판은 기본 5초마다 다음으로 넘어가고 마지막 다음에는 처음으로 순환합니다. home-banners.js의 DEFAULT_INTERVAL_MS는 변경 가능한 시연 설정이며 실제 광고 운영 정책이 아닙니다. 로딩 전 window.MOBTWIG_UI_CONFIG.bannerIntervalMs로도 조정할 수 있습니다. 현재 위치 카운터는 자동/수동 이동을 모두 반영합니다. 한 장/빈 목록에는 자동 전환 타이머나 정지/재개 버튼을 만들지 않습니다.

자동 넘김 정지/재개 버튼을 제공합니다. 모션 줄이기 설정은 기본 정지이며 명시적으로 재개하면 애니메이션 없이 이동합니다. 터치/드래그/수동 조작·배너 포커스·팝업·숨김 탭에서 멈추고 해제 후 새 간격을 기다립니다. 홈 이탈 시 타이머와 리스너를 정리하며 재진입·복귀 때 중복되거나 밀린 횟수만큼 이동하지 않습니다. 세션 내 사용자의 정지/재개 선택은 유형 전환과 홈 재진입에도 유지합니다.

이번 브라우저에서는 수정 전 탭별 폭 흔들림 자체는 재현되지 않았습니다. 수정 후 iframe 안팎·전 탭·모달의 숨김 스타일과 스크롤 가능, 폭/중앙 위치 일치, 자동 순환과 정지 사유·재개 간격·단일 타이머를 검사했습니다. 자세한 검증 범위와 타사 참고 한계는 ../FEATURES.md에 기록했습니다.

## 차단한 이용자·비공개 메모 (SFR-033 / 명세 v0.14)

**마이페이지 → 커뮤니티 관리 → 차단한 이용자**에서 이용자별 메모를 작성·조회·수정·삭제합니다. 초기 목록은 비어 있으며 ‘가상 차단 목록으로 시연하기’를 눌러 가상 이용자 3명을 추가합니다. 같은 닉네임도 계정 ID로 구분합니다. 아래 시연 도구에서 가상 닉네임을 바꿔 메모 연결이 유지되는지 확인할 수 있습니다.

메모는 작성한 시연 회원과 대상 ID별로 별도 로컬 저장소에 저장합니다. 재진입·재실행 후 유지되며 다른 로그인 회원의 UI에서는 보이지 않습니다. 저장 실패 시 편집창과 입력을 유지해 다시 저장할 수 있고, 메모 삭제는 차단 시연 상태와 다른 이용자의 메모를 바꾸지 않습니다. 입력은 일반 텍스트로 렌더링합니다. 실제 계정·민감한 개인정보를 입력하지 마세요. 실제 인증/서버 소유권 검증이나 브라우저 저장소 자체의 개인정보 보호를 완료한 것은 아닙니다.

차단 해제는 **가상 목록에서만 제거**합니다. 시연에서는 메모를 ‘해제 후 시연 보관 메모’에 보관하며 조회·수정·삭제·시연 목록 재추가가 가능합니다. 화면에도 이 임시 선택과 정식 정책 미정을 표시합니다. 실제 글/댓글/작품/알림 차단, 등록 위치, 해제 후 메모 보존/삭제·복구, 검색과 글자 수 상한 등 D-20 정책은 확정하지 않았습니다. 대상에게 메모를 공개하거나 알림·외부 전송을 생성하지 않습니다.

이번 반영은 이 폴더의 HTML 앱 미리보기이며 Expo 앱의 새 메모 화면은 미구현입니다. v0.13 커뮤니티 전체나 마이페이지의 비밀번호/사진 변경·키워드 숨김·도전과제는 이번 요청 범위에 포함하지 않았습니다. 기존 서재·찜·독서 기록·헤더·하단 메뉴를 보존했습니다.

저장 키는 `mobtwig-private-memos-v1:<회원 ID를 encodeURIComponent로 변환한 값>`입니다. 기존 독서 데이터 키를 재사용하거나 초기화하지 않습니다. 로딩/쓰기 오류와 손상 자료는 오류로 안내하며 정상 저장본을 보존합니다. 위 파일 수는 당시 기록이며, 현재는 `profile-editor.js`, 커뮤니티 모듈과 `community-assets/`를 포함한 폴더 전체를 함께 사용하세요.

메모 저장소 단위 테스트 8개와 실제 앱 미리보기 브라우저 검증으로 계정 분리·이전 계정 양식 거부, CRUD/재실행, 저장/삭제/읽기 실패와 재시도, 일반 텍스트 안전성, 닉네임 변경, 시연 해제/보관 및 360/390/430px 사용성을 확인했습니다. 운영 서비스 참고 범위와 Expo 구분은 [기능 개발 상태](../FEATURES.md)에 기록했습니다.
