# 개발용 이미지 자료 공유 및 배포 안내

팀원이 함께 사용하는 **test(테스트) 전용 이미지 자료**의 저장·배포 안내입니다. 기존 `server/mock/assets/`의 표지 16개와 배경 1개를 실제 서버의 정적 리소스 위치로 옮겼습니다. 화면·작품 정보를 검증하는 용도로 사용합니다. 업로드 API나 DB 자료는 추가하지 않았습니다.

## 용도와 준비 상태

| 항목 | 현재 구성 |
| --- | --- |
| 자료의 용도 | 팀원이 개발·테스트에 함께 사용하는 표지 16개와 배경 1개입니다. 실제 출간 정보나 운영 콘텐츠를 보증하는 자료가 아닙니다. |
| Git 관리 | 이미지 파일을 저장소에 포함합니다. 이 폴더에 업로드 파일 제외 규칙을 두지 않습니다. |
| 표지 위치 | `server/src/main/resources/static/media/covers/`의 도서·매거진·웹소설 폴더입니다. |
| 배경 위치 | `server/src/main/resources/static/media/backgrounds/`입니다. |
| HTTP 제공 | Spring Boot의 기존 정적 리소스 처리 방식을 사용합니다. 해당 파일을 포함한 서버를 빌드·실행하면 `/media/...`로 제공합니다. |
| mock 사용 | JSON은 `server/mock/fixtures/`에 유지하고 이미지는 위의 공용 폴더에서 읽습니다. |
| 운영 반영 | 해당 파일을 포함한 변경이 `master`에 반영되고 기존 배포가 성공하면 같은 이미지가 운영 API에도 포함됩니다. |
| 추가 구현 여부 | 파일 업로드 API·새 리소스 핸들러·Docker 마운트는 이번 작업에서 추가하지 않았습니다. |

현재 API 계약은 [API 명세서](API%20명세서.md), DB 필드는 [테이블 정의서](테이블%20정의서.md), 배포 절차는 [배포 안내](배포%20안내.md)에서 확인합니다.

## 폴더 구조

```text
teamproject/
├─ server/
│  ├─ mock/
│  │  ├─ index.mjs
│  │  └─ fixtures/
│  │     ├─ home.json
│  │     └─ works.json
│  └─ src/main/resources/static/
│     ├─ admin/
│     ├─ api-docs/
│     └─ media/
│        ├─ covers/
│        │  ├─ 도서/         # 표지 6개
│        │  ├─ 매거진/       # 표지 5개
│        │  └─ 웹소설/       # 표지 5개
│        └─ backgrounds/
│           └─ night-sky.png
└─ docs/
   └─ 이미지 저장소 구현 안내.md
```

이미지 17개는 원래 `mock/assets/`에서 사용하던 파일이며 내용은 변경하지 않았습니다. 원래 도서·매거진·웹소설 분류와 파일명을 유지했습니다. 공유할 테스트용 표지는 해당 `covers/` 분류에, 배경은 `backgrounds/`에 추가합니다.

## 파일 경로와 DB 주소

아래는 옮긴 실제 테스트 파일 `나를 돌보는 연습.png`의 경로입니다.

| 구분 | 위치 또는 값 |
| --- | --- |
| Git에 포함할 원본 | `server/src/main/resources/static/media/covers/도서/나를 돌보는 연습.png`입니다. |
| Maven 빌드 중 복사 위치 | `server/target/classes/static/media/covers/도서/나를 돌보는 연습.png`입니다. |
| 실행 JAR 내부 위치 | `BOOT-INF/classes/static/media/covers/도서/나를 돌보는 연습.png`입니다. |
| HTTP 요청 경로 | `/media/covers/도서/나를 돌보는 연습.png`입니다. |
| 작품 등록의 `imageUrl` | `/media/covers/도서/나를 돌보는 연습.png`를 입력합니다. |
| DB의 `book.cover_image_url` | 같은 `/media/covers/도서/나를 돌보는 연습.png`를 저장합니다. |

DB에는 Windows 파일 경로나 `src/main/resources/static` 같은 소스 경로를 저장하지 않습니다. 앱이 요청할 HTTP 경로를 저장합니다. 기존 [주소 검사](../server/src/main/java/com/mobtwig/work/WorkMetadata.java)는 API 서버 기준의 `/` 경로를 지원합니다.

로컬에서는 `http://localhost:8080/media/covers/도서/나를 돌보는 연습.png`, mock에서는 `http://127.0.0.1:8090/media/covers/도서/나를 돌보는 연습.png`, 운영에서는 `https://mobtwig.xn--3h3b098b.kro.kr/media/covers/도서/나를 돌보는 연습.png`로 접근하는 구성입니다. 한글과 공백은 HTTP 요청 시 URL 인코딩하여 사용합니다. 해당 파일을 포함한 버전을 빌드·배포한 뒤에 사용할 수 있습니다.

배경 예시는 `/media/backgrounds/night-sky.png`입니다. mock의 홈·상세 JSON도 같은 `/media/...` 경로를 사용합니다. 이전 `/assets/...` 주소는 새 경로로 변경해야 합니다.

## 서버 담당자의 자료 추가 순서

1. test(테스트)용 표지를 `covers/`의 해당 분류에, 배경을 `backgrounds/`에 추가합니다.
2. 실제 파일명과 확장자에 맞는 `/media/covers/...` 또는 `/media/backgrounds/...` 주소를 정합니다. 운영 컨테이너의 파일명은 대소문자를 구분하므로 참조 경로도 일치시킵니다.
3. 로컬에서 해당 파일을 포함한 서버를 실행하고 HTTP 주소에서 이미지를 확인합니다.
4. 기존 관리자 작품 등록의 `imageUrl`에 그 주소를 입력하고 홈·상세 응답에서 확인합니다.
5. 이미지 파일과 필요한 참조 변경을 같은 작업으로 검토합니다.
6. 팀의 승인된 Git·PR 절차를 통해 변경을 반영합니다. `master` 배포가 성공한 뒤 운영 이미지 주소를 확인합니다.

파일명이나 폴더를 바꿀 때에는 DB·SDUI 등에서 사용하는 참조 경로도 함께 확인합니다. 이 문서에서 커밋·푸시·병합·배포를 실행하지는 않았습니다.

## 기존 CI/CD에 포함되는 방식

```text
Git에 포함한 정적 이미지
→ CI의 Maven 빌드가 resources를 JAR에 포함합니다.
→ 검증한 동일 JAR로 Docker 이미지를 만듭니다.
→ master 배포가 운영 API 컨테이너를 교체합니다.
→ 운영 API가 /media/... 경로로 이미지를 제공합니다.
```

[CI](../.github/workflows/ci.yml)는 서버에서 `clean verify`를 실행하고 검증한 JAR를 보관합니다. [배포 워크플로](../.github/workflows/release.yml)는 이 JAR를 가져오며, [Dockerfile](../server/Dockerfile)은 `app.jar`를 이미지에 넣습니다.

[Docker 빌드 제외 규칙](../server/.dockerignore)이 소스 폴더를 직접 복사하지 않아도 정적 이미지는 이미 JAR 안에 포함되는 구조입니다. 이번 목적에는 별도 운영 업로드 폴더나 Docker bind mount를 추가할 필요가 없습니다.

배포 설정을 읽어 확인한 포함 경로입니다. 이번 자료 이동에서는 빌드·테스트·원격 접속·배포를 수행하지 않았으므로 실제 운영 반영이 완료되었다는 의미는 아닙니다. 이미지 17개의 원본 합계는 45,202,909바이트이며 빌드·배포물에 포함됩니다.

`develop` 반영은 팀원 간 코드·자료 공유와 CI 검증 단계이며, 실제 운영 배포는 기존 설정대로 `master` 반영 후 진행됩니다. 이전 버전으로 배포하면 그 버전에 포함한 이미지 구성으로 돌아갑니다.

## DB 자료와의 구분

이미지 파일의 배포가 DB의 작품 행을 자동 생성하거나 로컬 DB를 운영 DB에 복사하지는 않습니다. `mock/fixtures/`의 가상 작품 정보도 실제 서버의 응답이나 DB로 전환하지 않았습니다. 각 환경에서 등록한 작품의 `imageUrl`이 실제 배포된 이미지 경로를 가리키도록 관리합니다. 기존 DB에 `/assets/...`를 입력한 적이 있다면 해당 행도 새 경로로 수정해야 합니다.

개발용 공통 DB 자료도 자동 반영해야 한다면 별도 요구사항으로 범위와 적용 환경을 합의합니다. 이번 작업에서는 SQL이나 시드 자료를 추가하지 않았습니다.

## 실제 사용자 업로드를 구현할 때

현재 폴더는 Git으로 관리하는 개발·테스트 자료용입니다. 나중에 관리자나 사용자가 브라우저에서 파일을 업로드하는 기능을 구현하면, 그 파일은 배포 JAR와 분리한 영구 저장소에 보관하도록 별도로 설계합니다. 운영 호스트의 `C:\Mobtwig\uploads` 같은 경로는 그때의 후보이며 이번 작업에서 생성하거나 연결하지 않았습니다.

업로드 API·인증·파일 검사·용량 제한·파일명 생성·보관 및 백업 정책은 그 기능의 구현 범위에서 정합니다. 현재 API와 OpenAPI 명세에는 동작하지 않는 업로드 경로를 추가하지 않았습니다.

## 확인 기준

- [ ] 추가한 실제 이미지가 Git 변경 목록에 나타납니다.
- [ ] Maven 빌드 후 이미지가 `target/classes/static/media/`에 포함됩니다.
- [ ] 배포 JAR 안에서도 같은 상대 경로를 확인합니다.
- [ ] 로컬에서 이미지 주소가 200과 적절한 이미지 Content-Type을 반환합니다.
- [ ] 관리자 작품 등록과 앱의 홈·상세에서 해당 표지를 확인합니다.
- [ ] 승인된 `master` 배포 후 같은 경로로 운영 이미지를 확인합니다.

정적 리소스 제공 위치는 [Spring Boot 공식 문서](https://docs.spring.io/spring-boot/reference/web/servlet.html#web.servlet.spring-mvc.static-content)를 참고합니다.
