# 브랜치 이름 규칙

브랜치 이름은 작업의 목적을 쉽게 파악할 수 있도록 작성합니다.

1. 영문은 소문자로 작성합니다.
2. 공백 대신 하이픈(`-`)으로 단어를 연결합니다.
3. 작업 유형과 기능 또는 수정 대상을 이름에 포함합니다.
4. 이름은 작업 내용을 구분할 수 있을 정도로 간결하게 작성합니다.
5. 이름 끝에는 이슈번호를 포함합니다.

---

## 브랜치 이름 기본 형식

```text
작업유형-기능이름
```

| 브랜치 유형 | 사용 기준 |
| --- | --- |
| feature/ | 새로운 기능을 개발할 때 사용합니다. |
| bugfix/ | 일반적인 버그를 수정할 때 사용합니다. |
| docs/ | 문서화 작업을 할 때 사용합니다. |
| refactor/ | 기능 변경 없이 코드 구조를 개선할 때 사용합니다. |
| release/ | 배포 전 점검과 버전 정리 등 배포를 준비할 때 사용합니다. |

---

## 작성 예시

| 작업 내용 | 브랜치 이름 |
| --- | --- |
| 로그인 기능을 개발합니다. | `feature/login-#12` |
| 사용자 프로필 기능을 개발합니다. | `feature/user-profile-#14` |
| 로그인 오류를 수정합니다. | `bugfix/login-error-#15` |
| 보안 문제를 긴급하게 수정합니다. | `hotfix/security-#16` |
| 1.0.0 버전 배포를 준비합니다. | `release/1.0.0-#167` |
