# 브랜치 이름 규칙

브랜치 이름은 작업의 목적을 쉽게 파악할 수 있도록 작성합니다.

1. 영문은 소문자로 작성합니다.
2. 공백 대신 하이픈(`-`)으로 단어를 연결합니다.
3. 작업 유형과 기능 또는 수정 대상을 이름에 포함합니다.
4. 이름은 작업 내용을 구분할 수 있을 정도로 간결하게 작성합니다.

---

## 브랜치 이름 기본 형식

```text
작업유형-기능이름
```

| 브랜치 유형 | 사용 기준 |
| --- | --- |
| feature | 새로운 기능을 개발할 때 사용합니다. |
| bugfix | 일반적인 버그를 수정할 때 사용합니다. |
| hotfix | 배포된 서비스의 오류나 보안 문제를 긴급하게 수정할 때 사용합니다. |
| release | 배포 전 점검과 버전 정리 등 배포를 준비할 때 사용합니다. |

---

## 작성 예시

| 작업 내용 | 브랜치 이름 |
| --- | --- |
| 로그인 기능을 개발합니다. | `feature-login` |
| 사용자 프로필 기능을 개발합니다. | `feature-user-profile` |
| 로그인 오류를 수정합니다. | `bugfix-login-error` |
| 보안 문제를 긴급하게 수정합니다. | `hotfix-security` |
| 1.0.0 버전 배포를 준비합니다. | `release-1.0.0` |

---

## 브랜치 관리 예시

현재 프로젝트의 기준 브랜치인 `master`에서 작업별 브랜치를 만들어 개발합니다.

```text
master
 ├─ feature-login
 ├─ feature-user-profile
 └─ bugfix-login-error
```

작업이 완료되면 PR을 통해 검토한 뒤 `master`에 병합합니다.
